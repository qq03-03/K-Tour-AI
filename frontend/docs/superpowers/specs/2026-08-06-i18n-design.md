# 다국어(i18n) 지원 설계

## 목적

검색 결과/상세 페이지의 콘텐츠와 화면 UI 문구를 한국어/영어/일본어/중국어 4개 언어로 전환할 수 있게 한다.

## 범위

- **콘텐츠 번역**: 드라마 제목, 장소명, 지역, 계절, 시간대, 설명, mood/activity/scene_elements 태그. 백엔드 전달본(`K-Tour-AI_백엔드전달_v2/data/display_translations.json`)의 실제 번역 데이터를 그대로 사용한다.
- **UI 문구**: 메뉴, 버튼, 안내 문구 등. 백엔드 전달 데이터에 없으므로 직접 4개 언어로 작성한다.
- **검색 자체는 언어와 무관하게 항상 원본 텍스트 기준으로 동작한다.** 백엔드 계약(`docs/display_localization_contract.md`)에 "검색 순위와 임베딩은 변경하지 않고, 결과 카드의 표시 필드만 요청 언어로 바꾼다"고 명시되어 있으므로, `searchSegments.js`의 검색/필터 로직은 변경하지 않는다.

## 데이터 준비

### 콘텐츠 번역: `src/data/segmentTranslations.js`

`display_translations.json`의 45개 레코드를 `display_translation_overrides.json`의 사람 검수 교정을 병합한 뒤, `segment_id + keyframe_id`를 키로 하는 정적 객체로 만든다. 런타임에 두 파일을 매 요청마다 병합하지 않고, 데이터 준비 단계에서 한 번만 병합한 결과를 커밋한다 (정적 사이트이므로).

```js
export const segmentTranslations = {
  'WLGYT_01_SCENE_01__WLGYT_01_SCENE_01': {
    ko: { drama_title, place_name, region, season, time_of_day, description, mood: [...], activity: [...], scene_elements: [...] },
    en: { ... },
    ja: { ... },
    zh: { ... },
  },
  ...
}
```

### UI 문구: `src/i18n/strings.js`

```js
export const strings = {
  ko: { nav_home: '홈', nav_search: '검색', ... },
  en: { nav_home: 'Home', nav_search: 'Search', ... },
  ja: { ... },
  zh: { ... },
}
```

## 언어 상태 관리

`src/i18n/LanguageContext.jsx`:

- `LanguageProvider`가 `App.jsx` 최상단을 감싼다.
- 초기값: `localStorage.getItem('ktourai_lang')`, 없으면 `'ko'`.
- `setLang(lang)` 호출 시 상태 변경 + `localStorage.setItem('ktourai_lang', lang)`.
- `useLanguage()` 훅이 `{ lang, setLang, t }`를 반환한다. `t(key)`는 `strings[lang][key]`를 찾고 없으면 `strings.ko[key]`로 fallback한다.

## 콘텐츠 로컬라이즈: `src/lib/localizeSegment.js`

`display_localization.py`의 `localize_search_result`를 이식한다.

```js
export function localizeSegment(segment, lang, translations = segmentTranslations) {
  const keyframeId = `${segment.segment_id}__${segment.segment_id}` // keyframe_path 파일명 stem과 동일 규칙
  const record = translations[keyframeId]
  const localized = record?.[lang] ?? record?.ko
  if (!localized) return segment
  return { ...segment, ...localized }
}
```

- fallback 순서: 요청 언어 → 한국어 → 원본(`segment` 그대로 반환).
- `ResultCard`, `Detail` 페이지에서 렌더링 직전에 `localizeSegment(segment, lang)`을 적용한다.
- `SearchResults`/`Home`의 검색·필터 로직에는 적용하지 않는다 (원본 텍스트 기준 유지).

## 컴포넌트 반영

- **Header**: `KO / EN / JA / ZH` 4개 버튼. 현재 언어는 강조 표시. 클릭 시 `setLang()`. 메뉴 라벨은 `t()`로 교체.
- **Home**: Hero 문구, DramaSection/SeasonSection/ThemeSection 제목, SearchBar placeholder를 `t()`로. `seasons.js`/`themes.js`의 `label`을 `{ ko, en, ja, zh }` 객체로 바꾸고 `lang`에 맞는 라벨을 선택해 렌더링.
- **SearchResults**: "검색 결과 N건", "지도로 보기/리스트로 보기"를 `t()`로. `results.map()`에 넘기기 전 각 segment에 `localizeSegment` 적용.
- **Detail**: 마찬가지로 `localizeSegment` 적용. 고정 문구는 `t()`로.
- **KakaoMap, EmptyState, Footer**: 하드코딩 문구를 `t()`로.
- **About**: 파이프라인 단계 라벨·상태 문구를 `t()`로.

## 테스트

- `localizeSegment`: 언어별 필드 치환, 번역 없는 세그먼트는 원본 반환, ko fallback.
- `LanguageContext`/`useLanguage`: 초기값 localStorage 반영, `setLang` 시 저장 및 상태 갱신, `t()` fallback.
- 언어 버튼 클릭 시 화면 문구가 바뀌는 것을 확인하는 컴포넌트 테스트(Header, 최소 1개 페이지).

## 에러 처리

번역 레코드가 없는 세그먼트나 알 수 없는 `lang` 값은 원본(한국어) 그대로 표시하고 앱이 깨지지 않는다. 백엔드 계약의 fallback 규칙(요청 언어 → 한국어 → 원문)과 동일하게 맞춘다.
